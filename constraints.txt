# Exact runtime pins for the image (python:3.12.15-slim), applied with
# `pip install -c` by the Dockerfile. garmin-mcp itself is installed with
# --no-deps, so nothing here pins it.
#
# Why mcp 2.3.0 although upstream's pyproject says mcp>=1.28.1,<2:
# claude.ai and Claude Code open with `server/discover` at protocol version
# 2026-07-28, which only mcp 2.x serves (1.28.1 answers 400 "Unsupported
# protocol version"). Upstream (garmin_mcp 202913fd, issue #344) is not ported
# to 2.x; ext/mcp2_compat.py adapts mcp 2.x's MCPServer to the FastMCP API
# upstream calls, so the cap is bypassed on purpose. `pip check` therefore
# reports exactly one conflict, "garmin-mcp 0.1.0 has requirement mcp<2".
#
# Generated 13 Nov 2026 by a real resolve on python 3.12 of upstream's
# dependencies at that commit plus mcp==2.3.0:
#   pip install --dry-run --report r.json -c <old pins> \
#     python-dotenv==1.2.2 garminconnect==0.3.2 requests==2.33.0 \
#     "fitparse>=1.2.0" mcp==2.3.0
# The Garmin-side packages (garminconnect, curl-cffi, ua-generator, requests,
# certifi, urllib3, charset-normalizer) keep the pins of upstream's uv.lock;
# idna moved because httpx2 (mcp 2.x) needs >=3.18. Regenerate when bumping
# GARMIN_MCP_REF or mcp.
#
# Re-checked 17 Nov 2026: garmin-connect-personal-api-python 1.0.0 adds no other
# package (it needs requests>=2.31,<3); certifi raised to 2026.10.23 for
# PYSEC-2026-4320 (fixed in 2026.10.18).
