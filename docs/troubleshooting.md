# Troubleshooting

Logs: on Railway, `railway logs` or the service's logs in the dashboard; with Docker,
`docker compose logs app` in the project folder (`docker compose logs tunnel` for the tunnel).
Below, "the server log" means these.

Never paste the output of `docker compose config`, `docker inspect`, `railway variable list --kv`
or `railway environment config --json` into an issue or a chat: they show your secrets.

| Symptom | Cause | Fix |
|---|---|---|
| `401` | Not signed in, or the sign-in expired or was revoked (for example after a new owner secret); or a wrong static token | claude.ai: Customize → Connectors → Garmin → **Reconnect** (or the **Connect** card in a chat), then type the owner secret. Claude Code: `/mcp`, sign in again. Static token: the header must be `Authorization: Bearer <token>` |
| `410` | The removed `https://<your-app>.up.railway.app/<token>/mcp` form | Use `https://<your-app>.up.railway.app/mcp` and sign in ([Connect Claude](connect-claude.md)); see [Moving from the token-in-URL version](maintenance.md#moving-from-the-token-in-url-version) |
| `403` with `Origin not allowed` | A browser-based client sent an `Origin` header this server does not allow | Add that origin to `ALLOWED_ORIGINS` (comma-separated), or set `ORIGIN_CHECK=off` |
| `429` from the sign-in | Too many sign-in requests from one address | Wait the seconds in `Retry-After` (at most an hour), then start again from claude.ai |
| claude.ai cannot finish adding the connector | The URL differs from the one the server names: a trailing slash, `http://`, or a custom domain without `PUBLIC_URL`; or the deployment is not up | Use the connector URL exactly as your deploy printed it, and run `test-connector.sh` with the same origin. For a custom domain, set `PUBLIC_URL` ([Settings](deploy-railway.md#settings)), then remove the connector and add it again |
| The sign-in page says the link expired or was already used | It works once, for 10 minutes; three wrong secrets cancel it | Start again from claude.ai (or `/mcp` in Claude Code) |
| claude.ai cannot reach a Docker server (it cannot add the connector, or every call fails) | The tunnel is down; the route's service URL is not `http://app:8080`; or `PUBLIC_URL` in `.env` is not `https://` plus the tunnel's hostname | `docker compose ps`: `app` must be healthy and `tunnel` running. `docker compose logs tunnel` shows whether the tunnel connected. Check the route in Cloudflare (**Networking → Tunnels**, your tunnel, **Routes**) and `PUBLIC_URL`; after a change in `.env`, run `docker compose up -d --force-recreate app` |
| Claude gets `403` or `429` from a Docker server, and the server log shows no such request | A Cloudflare feature blocks Claude: Bot Fight Mode, the AI agent policy set to Block, Under Attack mode, a WAF, rate-limiting or cache rule, or an Access application | Turn it off for this hostname, as [Cloudflare settings that block Claude](deploy-docker.md#cloudflare-settings-that-block-claude) says |
| `curl https://<your-host>/healthz` or `test-connector.sh` gets a Cloudflare page (`Just a moment...`, a challenge, or a redirect to `<team>.cloudflareaccess.com`), not `200` | Bot Fight Mode or Under Attack mode challenges the call, or a Cloudflare Access application guards the host name. Claude cannot pass either | Turn off Bot Fight Mode and Under Attack mode, and delete the Access application for this host name ([Cloudflare settings that block Claude](deploy-docker.md#cloudflare-settings-that-block-claude)); then `./scripts/setup.sh --check` |
| `scripts/setup.sh` says Docker Compose is too old, or that only `docker-compose` (Compose v1) is installed; or `docker compose` answers `'compose' is not a docker command` | This setup needs the Compose plugin, version 2.20 or newer (`docker compose`, with a space). The old `docker-compose` v1 is not supported | Update Docker Desktop, or on Linux install the `docker-compose-plugin` package from Docker's own repository ([Docker](https://docs.docker.com/compose/install/linux/)). `docker compose version` must show 2.20 or newer |
| The Docker server starts, but claude.ai cannot finish adding it, or the sign-in page names another address | The host name differs between the tunnel's route in Cloudflare, `PUBLIC_URL` in `.env` and the connector URL; they must be the same, with `https://` | Fix the route or `PUBLIC_URL` (`./scripts/setup.sh` asks again if you answer no to keeping `.env`), run `docker compose up -d --force-recreate app`, then remove the connector in claude.ai and add it again with `https://<your-host>/mcp`. `./scripts/setup.sh --check` runs `test-connector.sh` against `PUBLIC_URL` |
| `/readyz` 503 | `full` mode: the Garmin login is not done or still loading. `key` mode: Garmin refused the key when the server started | `full`: do the [Garmin login](garmin-login.md#full-mode-the-one-time-login) and wait 30 s. `key`: [Renew the Garmin key](maintenance.md#renew-the-garmin-key-key-mode). Check the server log |
| The deployment keeps failing at startup; the server log shows `launch: config error:` lines | A setting the server checks: `GARMIN_AUTH` missing or not `full` or `key` (the line starts `launch: config error: GARMIN_AUTH`), `GARMIN_PERSONAL_API_KEY` missing or malformed in `key` mode or not empty in `full` mode, `REPORT_TZ` missing or not a valid IANA zone, `GARMIN_ENABLED_TOOLS` naming a tool that is not in `config/enabled-tools.txt` (in `key` mode, `config/enabled-tools-key.txt`), `GARMIN_DISABLED_TOOLS` set, or a sign-in setting (`OWNER_SECRET` missing, too short or too simple; `PUBLIC_URL` not an https origin; `MCP_BEARER_TOKEN`, `AUTH_DB` or `ALLOWED_REDIRECT_URIS` malformed) | Fix the variable each line names ([Settings](deploy-railway.md#settings), [Tools](tools.md)); Railway redeploys by itself; with Docker, run `docker compose up -d --force-recreate app` after you fix `.env`. `./scripts/deploy.sh` generates a missing `OWNER_SECRET`. For `AUTH_DB: cannot open ...`, deleting the file signs everyone out and starts fresh |
| The deployment keeps failing at startup; the server log shows `entrypoint: FATAL: PORT must ...` | `PORT` is not a whole number from 1 to 65535, or it is `8000`, the internal port Caddy forwards to | Delete the `PORT` variable you set on Railway (Railway sets `PORT` itself); with Docker, keep `PORT: "8080"` in `compose.yaml` |
| Tool call fails right after a deploy | The only container is being replaced | Wait about a minute and retry |
| Garmin login keeps failing (`full` mode) | Garmin rate limit or lockout | Wait 1–24 h; check you can log in at connect.garmin.com |
| `server/discover` answers `400 Unsupported protocol version` | The running image is still on mcp 1.x (an old deployment, or a rollback) | Deploy the current repo; `scripts/test-protocol.py` should then pass its `modern` check |
| `400` with `"header does not match"` (code -32020) | A 2026-07-28 client sent `Mcp-Method` / `Mcp-Name` / `MCP-Protocol-Version` headers that disagree with the request body. Caddy forwards these headers unchanged | Client-side bug; retry with another client, or check a proxy in between is not rewriting headers |
| `413 Request body too large` | mcp 2.x rejects request bodies over 4 MB | No tool here needs that; check the client |
| A tool answers `Error: Garmin login missing or expired. ...` (`/readyz` can still say 200) | `full` mode: the Garmin login on the server is missing, or its tokens expired | Redo the [Garmin login](garmin-login.md#full-mode-the-one-time-login); see [Maintenance](maintenance.md#garmin-login-expired-full-mode) |
| In `key` mode, `/readyz` says ready but tools say the Garmin login is missing or expired | `/readyz` 200 means Garmin did not refuse the key when the server started, or the server reused a saved access token. The key was deleted or has expired since | Create a new key and put it in place: [Renew the Garmin key](maintenance.md#renew-the-garmin-key-key-mode) |
| A tool answers `Error: Garmin rate limit. ...` | Garmin refuses calls from the server for a while (too many calls or logins in a short time). For 15 minutes after that, the server's call guard answers the same text without calling Garmin, so retries cannot extend the block; the server log then shows `Garmin call refused by the call guard: rate_limited`. A daily or weekly report in which only some sources hit the limit still answers (those sources read `Garmin rate limit`), and the same 15 minutes start | Stop for at least 15 minutes, then try one call. With history search on, a rate limit also pauses the worker for 6 hours |
| The deployment keeps failing at startup; the log shows `launch: config error:` lines about `TRACING`, `OTEL_...`, `HISTORY_...`, `DATABASE_URL` or `ROLE` | An optional feature's setting is wrong or incomplete: `TRACING=on` without an https `OTEL_EXPORTER_OTLP_ENDPOINT`, an `OTEL_...` variable the server sets itself, `HISTORY_SEARCH=on` without `DATABASE_URL` (or, in `full` mode, `HISTORY_TOKEN_KEY`), `ROLE=worker` without `HISTORY_SEARCH=on`, or an image built without `HISTORY=1`. No line shows a secret's value | Fix the variable the line names ([Settings](deploy-railway.md#settings)); to turn a feature off, delete its switch or set it to `off` |
| Tracing is on but the tracing service shows nothing | A wrong endpoint or auth header, or the service refuses the data. The server log has one `telemetry: export failed: <kind>` line per kind of failure every 10 minutes; tool calls are never slowed | Check `OTEL_EXPORTER_OTLP_ENDPOINT` and `OTEL_EXPORTER_OTLP_HEADERS` against your service's OTLP settings ([Tracing](tracing.md)) |
| The history tools are missing, or say the history is empty | `HISTORY_SEARCH` is off on the app, `HISTORY_FORGET` is still set, the worker or cron service is not running, or the backfill has not reached that far yet | Check the app's log for `history search: on`; delete `HISTORY_FORGET`; check the worker's log ([History worker](history-worker.md)). Refresh the tools list in claude.ai after turning it on |
| The worker's jobs wait with `token_stale` (`full` mode) | The worker reads the Garmin login the app stored in Postgres, and it is missing or expired | Use a Garmin tool once so the app refreshes the login, and check that `HISTORY_TOKEN_KEY` is the same on the app and the worker |
| A tool answers `Error: Garmin Connect did not answer ...` | A timeout, a network problem or an error on Garmin's side | Try again in a few minutes; check that connect.garmin.com works |
| A tool answers `Error: Internal server error (ref <ref>) ...` | A failure inside the server | Search the server log for `ref=<ref>`: that line has the tool, the original error and a traceback |
| A tool answers `Error: Invalid input: ...` | The client sent an argument the tool rejects | Fix the argument it names; dates are YYYY-MM-DD |
| New tools missing in claude.ai | claude.ai keeps the tool list it saw when the connector was added | Customize → Connectors → Garmin → **Refresh tools list**, then start a new chat. Check the tool is in `config/enabled-tools.txt` (in `key` mode, `config/enabled-tools-key.txt`) and deployed |
| A tool that the recipes or another guide name is missing | In `key` mode the server lists only the tools Garmin's Personal API can serve | Expected: [Tools](tools.md) lists the tools of each mode |
| The report says incomplete (`Incomplete data`) | Neither sleep nor Training Readiness had reached Garmin Connect when it was built | Open the Garmin Connect app to sync the watch; the routine's later runs fill the report in, or ask "How am I today?" |
| `deploy.sh` stops with "Could not read the service variables" | Railway was unreachable or the login expired; it stops before changing anything, so the owner secret is never replaced by accident | `railway whoami`, `railway login` if needed, then run it again |
| `deploy.sh` stops: `GARMIN_ENABLED_TOOLS` names tools that `GARMIN_AUTH=key` does not have | Key mode serves only the tools in `config/enabled-tools-key.txt`, and the server would refuse to start | Remove those names from `GARMIN_ENABLED_TOOLS` (or delete it: `railway variable delete GARMIN_ENABLED_TOOLS`), or keep `GARMIN_AUTH=full`; then run it again |
| `deploy.sh` stops at "Public domain" | The service has no Railway domain yet (or only a custom one) | Create one in the dashboard (Settings > Networking > Generate Domain), or set `PUBLIC_URL` to your custom domain; then run it again |
| Rides are classed hard too often | The cycling FTP stored in Garmin Connect is out of date, so ordinary power targets sit above 0.91 × FTP | Update your FTP in Garmin Connect; `thresholds_athlete` in the status shows the value used |

Each failed tool call writes one line to the server log:
`tool error: tool=<name> group=<group>: <original error>`, with `ref=<ref>` and a traceback
for internal errors. A missing record answers `No data: ...`, which is not an error.
